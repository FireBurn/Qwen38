# Dynamic projection width diagnostic

The mapped, intrusive empty-KV comparison found exact first-normalization values and different Q4_K dynamic-projection outputs when combining two five-token blocks. Source uses a matrix-vector pipeline for up to eight columns and a different matrix path above eight. To test whether width selection explains the first difference, build a diagnostic candidate that retains the two-sequence graph but calculates only the first-layer attention-side dynamic projection in two five-column operations and concatenates them. All layers use this guarded diagnostic for the attention-side projection; other graph operations remain batched. Compare the captured first-layer dynamic projection, convolution taps and downstream values against the split baseline on the same fixed synthetic input. This diagnostic may introduce additional dispatches and is not a proposed speed optimization or numerical qualification of other tensors. In-process library/driver mappings, fault monitoring and the previous process-local overrides are required; stop on faults or invalid/missing capture. No timing claims.
