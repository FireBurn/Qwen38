# Initial DFlash2 lattice check

Using the installed server executable, launch two isolated serial servers with private, same-build baseline and candidate libllama libraries, a common instrumented llama-common and identical ggml libraries. Verify their actual process mappings, model identity and 1DW/no-transfer-queue driver controls. The audit hook saves full DFlash2 lattice rows with dimensions before they are sampled. Each server receives the same seeded 16-token warmup and 32-token synthetic request with DFlash maximum width 4 and the observed sampler/context configuration. Record response hashes, acceptance counters, every lattice byte and GPU error deltas. Abort on first fault, competing inference, wrong library map, response failure or timeout; do not retry. Compare complete captures byte-for-byte and responses separately. Capture files remain private; publish hashes and summaries. This is an initial single-sequence short-context diagnostic, not an exhaustive correctness, stochastic-distribution, multi-sequence or timing qualification. Maintain the GPU hold otherwise.
