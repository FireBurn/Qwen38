# Two-slot DFlash selector check

Build two private llama libraries from the already reconstructed sources, adding the same environment-gated graph-construction trace to each. The candidate retains its selector change; the baseline does not. Use the same private instrumented common and ggml libraries. Start each arm serially with two server slots and submit two seeded requests concurrently, using equal-length prompt copies and bounded generation. Capture response hashes and per-call full lattice rows, verify mappings and graph trace, and compare the lattice record multiset as well as per-request output/acceptance counters. A multiset permits different ordering of concurrent requests, not numerical differences. Require a trace of at least one graph with two sequences; if scheduling produces none, the multi-sequence question is inconclusive. This check is not a speed measurement. Apply one-dword-copy/no-transfer-queue overrides and stop on faults, failed process, unverified mapping or output mismatch, without retry. Keep all captures private and the general GPU hold active.
