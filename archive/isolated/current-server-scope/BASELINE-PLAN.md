# Bounded current-server baseline

Run one fresh local-only installed llama-server process with the historically observed Q3 target, current cached DFlash2 Q4 draft, MTP/DFlash server flags, temperature/top-k/top-p, 327680 context limit and other recorded options. Use the cached local model files and an ephemeral loopback port. Set only GPU selection and one-dword buffer-copy override in the child environment; the override was used successfully in bounded post-fault tests, but differs from the observed server environment, which was not captured. There is no candidate in this one-process baseline and no performance improvement claim.

After readiness, send a synthetic warmup and one fixed 128-token chat request with seed 1234. Record model/build identity, command arguments, request settings, output hashes, timings, draft counts, observed CPU/build/runqueue/GPU telemetry and any new device errors. Stop on competition, server failure, timeout or a new GPU fault. Shut down only the child process group on completion. Do not retry, modify the user's server/settings or send requests to an existing service. A context allocation limit is not a populated 327k context; this baseline uses a short prompt. Subsequent matched comparisons need a predeclared A/B plan and appropriate stochastic output-quality checks.
