# Bounded top-k control and candidate qualification

Allow exactly two serial fresh GPU processes: reconstructed baseline, then scoped 512-chunk candidate, using only one 248320-element row with unique finite data and K=20. The driver gets one-dword-copy and disabled-transfer-queue process-local overrides, as in the later post-fault current-server checks. Each process gets a 30-second timeout. Capture executable/backend hashes, process mappings, complete stdout/stderr and kernel error deltas. Stop before candidate on any baseline fault, timeout, invalid index, missing mapping or disagreement with a CPU top-20 oracle; stop immediately on candidate fault or oracle mismatch. Do not retry. The output index order is compared too, because backend sampling can depend on order. Passing this single bounded case does not qualify ties, NaNs, multiple rows, long contexts, stochastic sampling, performance or the underlying fault. The prior broad boundary runner remains quarantined and the general hold stays in place.
