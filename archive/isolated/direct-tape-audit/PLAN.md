# Audit device-local mapped tape and existing reader completion

Derived privately from current one-row-gather host. Same bounds shader and original uploads; audit NEVER writes GPU tape from CPU. Opt-in AUDIT requests DEVICE_LOCAL|HOST_VISIBLE|HOST_COHERENT for32MiB tape on strictR9700, falling back to DEVICE_LOCAL. Original HOST_VISIBLE staging remains separate. Records actual memory flags/map pointer and per-graph eligibility.

Dedicated tape-reader completion starts true for newly allocated buffer, becomes false when a bindless mega dispatch is recorded, and becomes true only after the existing successful full ctx fence wait (same reader owner). The wait helper is called only by synchronize, which ends/flushes/submits pending compute commands before putting its full completion fence behind them. Almost-ready fence alone never qualifies. New input-transfer/compute contexts can exist while tape reads from the previous graph have completed, so this is more precise than assuming an entirely idle backend. No new waits. Serialize-submission mode rejected for eligibility until its separate completion semantics are qualified; verify/nonbindless/foreign-owner paths excluded.

Potential direct follow-up must freeze eligibility for a graph, require monotonic nonoverlapping physical ranges, keep fallback original copy for unqualified graphs and flushes outside active graph, guard backend/context/buffer lifetime, and retain every counter/barrier/dispatch/submission. Queue submission supplies host-write availability for HOST_COHERENT mapping; CPU may not overwrite in-flight tape. Reference Khronos synchronization chapter submission-host-writes. Audit is resource/lifetime evidence only, not direct-path speed or correctness qualification.
