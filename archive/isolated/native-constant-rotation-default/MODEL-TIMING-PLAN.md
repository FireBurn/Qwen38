# Native-default immutable rotation cache timing

Predeclared before this candidate's throughput measurement. Compare stock core, the identical private core with cache disabled, and that core with cache enabled, all with the original stock Vulkan backend, native allocation/queue/suballocation/submit defaults, same model, sampler, MTP, driver, context and 512-request-token workload. Use 12 symmetric six-process blocks, alternating cyclic order and reverse, 24 fresh processes per arm. Primary is cache-enabled versus disabled private core; stock versus enabled is a secondary whole-configuration comparison. Exclude no arms and preserve all results.

Require 530 raw target rows per private mode and repeated-clear test, exact output tokens and counters per timed process, unchanged binaries and driver, and no new GPU errors. Cache diagnostic logging is disabled while timing because the existing audit logs every bypass. Thus feature activation is established by the identical pinned core and opt-in flag plus correctness witnesses; allocation fallback warnings invalidate an enabled process. Steady throughput excludes the first 16 tokens; report generation, process time, clocks, power and memory separately.

For each pair, match blocks only when both mode means differ by at most 5 percentage points CPU busy, two build processes and max(4, 15% of mean) runnable threads; require valid telemetry. Report all blocks and matched geometric effects with descriptive t intervals; at least four matched blocks required. No quiet-load gate, resampling, pooling or clock matching. Positive discovery alone is not confirmation. If the matched primary interval excludes zero in favor of the cache, run a separately predeclared independent confirmation before making a gain claim.
