# Q6_K scale handoff through subgroup shuffle

Private candidate replaces only op01 scale LDS handoff with subgroupShuffle. Four 16-lane cohorts each work on a distinct superblock; the source lane is ix*16+s_offset+{0,2,4,6}. The tail predicate is uniform within each cohort, so every referenced source lane remains active. Float scale conversion, dequantization, FMA order and reduction are unchanged. Physical wave64/virtual 64-lane mapping is required, as in the current reference.

Build script exhausts cohort/source ownership for 1..256 blocks per row, then compiles and validates SPIR-V. No compiled resource allocation or GPU correctness result exists until checks.json is produced. First GPU probe uses only 16 workgroups via the existing serialized private guard. No full-residency launch or timing adoption is authorized by CPU proof alone.

This targets shared memory writes/reads and subgroup memory synchronization in Q6, which accounts for approximately 2.49 GB of matrix weight reads in the historical decode audit. It does not reduce those weight bytes. A subgroup shuffle may still lower to an LDS cross-lane instruction, so actual ISA and timing must decide whether this is useful. Full model speed remains unproven.

Build completed and SPIR-V validated; 2,105,344 CPU source-lane cases passed. Both nine-frame short/long probes at 16 workgroups passed bit identical, with the intended backend verified. Actual allocation is 96 VGPRs, 22 spilled SGPRs, no spilled VGPRs, 16 KiB LDS and no scratch. Code size is 239,712 bytes versus reference 241,132; spilled SGPR count is down from 24. These are allocation/code results, not speed evidence. The 192-workgroup, 65-frame short/long stress runner was started with 64 spare groups and serialized through the private guard. Completion must be established from stress.json and terminal process state before any claim of passing that gate.

Stress runner completed successfully: both 65-frame prompts are bit identical at 192 groups, with no native operations (including FA) in the last 32 graphs. This covers one/two/three-block tails and odd output rows with fixed deterministic data; it does not exhaust data patterns.
