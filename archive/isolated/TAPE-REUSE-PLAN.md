# Next host-side redundancy candidate: unchanged resident tape

Read-only native tape audit: final two saved4K decode graphs both1971 dispatch records, all1971 keys/workgroups/PCs/buffer ranges identical. GPU input contents can change while these descriptors remain fixed; padded FA KV extent can stay constant within a256-token block. This is BEFORE mega fusers and not proof of actual uploaded tape invariance. native-tape-invariance-audit.json is a direction only.

Current flush always memcpy's the full serialized record range into mapped stage and enqueues copyBuffer into GPU tape. Bindless tape has two16MiB parity halves in one32MiB buffer. Each graph's segment offsets/ranges can vary during native slot-learning, context boundaries and fusions. A safe exact-byte cache should index physical absolute tape offset, not segment ID or graph hash.

Potential implementation: per256-byte record validity bits for both parity halves, use retained mapped staging bytes as CPU shadow. Cache hit requires every record valid AND memcmp of entire exact byte range equal. On hit skip only CPU memcpy and GPU copyBuffer; keep original counters, counter clears, barriers, descriptor binds, dispatch, submissions and parity behavior. On miss copy bytes and mark corresponding records valid only when the matching GPU copy is recorded successfully. Overlapping writes naturally update the physical-address shadow/valid bits; no stale segment-key assumptions. Disable outside bindless/verify0 and keep fallback. GPU shader must never write tape, and no other writer may bypass validity updates. Lifetime of GPU tape/stage/context must invalidate bits; exception/cancellation path must clear trust or require backend termination. Queue submission order and no canceled recorded upload are part of the proof; do not infer completion merely from host recording. A CPU mirror test should cover overlap, changed sizes, uninitialized ranges, parity, changed records and invalidation.

First make an audit-only private host that reports exact uploaded-byte equality per range without skipping anything. If many bytes/segments really repeat, implement cache and validate9/65prompts, natural128 and actual4Kcoverage, then alternating micro and full timing. No driver or shared tree edits.
