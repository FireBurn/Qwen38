# Q3 weight-layout alignment prototype

**The padded layout passes correctness checks and improves isolated Q3 GPU timing in two under-load runs. A stock-backend model speedup remains unconfirmed.**

Native Q3_K blocks occupy 110 bytes. The shader combines 16-bit loads into 32-bit words because block alignment alternates. This prototype preserves all 110 original bytes and appends two padding bytes, giving a 112-byte stride. It adds 1.82% to Q3 storage, not to the entire model's weights. It does not requantize or edit the GGUF model.

Three variants distinguish layout from source-level load changes:

1. Native 110-byte blocks and original halfword-load code.
2. Padded 112-byte blocks with the original halfword-load expressions.
3. Padded blocks with explicit 32-bit load expressions.

The native control modules compile byte-identically to the recorded controls. All three reduction modes build and validate for each variant. Candidate SPIR-V layout strides are checked. CPU round-trip tests preserve every original byte across 4,096 random blocks and pass 262,144 packed-word comparisons. [Build/layout checks](../archive/isolated/q3-pad112/build.json), [CPU proof](../archive/isolated/q3-pad112/layout-proof.json).

## Capped GPU results

720 dispatch checks pass: three layouts × C1/C2 × five K sizes × six row counts × four patterns. This includes 240 native controls and 480 padded/native byte comparisons. Every dispatch also passes an independent scalar CPU oracle check, input-immutability checks and 256-byte buffer guards. There are no new target-driver errors.

The probe fixes **three rows per workgroup**, wave64 and at most 16 physical workgroups. This is diagnostic geometry, not the production C1/C2 one-/two-row geometry. Only the subgroup/no-shared-memory reduction was executed; the other reductions were build-validated.

| Layout | C1 instructions / VMEM instructions | C2 instructions / VMEM instructions |
|---|---:|---:|
| Native 110 | 5717 / 328 | 8974 / 509 |
| Padded, original halfword expressions | 4969 / 244 | 7904 / 383 |
| Padded, explicit word expressions | 4969 / 244 | 7904 / 383 |

VGPRs remain 48 for C1 and 60 for C2; LDS, scratch and spills remain zero. The two padded variants have identical reported compiled-shader hashes and resources. Padding alone therefore enables the compiler's load coalescing; an explicit word rewrite provides no additional observed code-generation benefit. These are static compiler counts, not speed or bandwidth measurements. [GPU checks and statistics](../archive/isolated/q3-pad112/diagnostics/checks.json).

## Production geometry and under-load timing

An additional **864 dispatch checks** use the production wave64 row geometry: one row per workgroup for C1 and two for C2. K=5120 is included. All native/padded outputs match bit for bit, pass the scalar CPU oracle and retain input bytes and guards; no new driver errors occur. Native/padded instruction counts are 2272/2053 for C1 and 6260/5556 for C2. VMEM instruction counts fall from 128 to 100 and 358 to 274 respectively; both use 48 VGPRs with zero LDS/scratch. [Production checks](../archive/isolated/q3-pad112/production-diagnostics/checks.json).

Two independent timing passes each contain 96 arms, using three fixed symmetric four-arm blocks for every shape/cache condition. The repeat reverses starting order. Each arm timestamps 4096 dispatches on the GPU, with equal barriers and recording outside the queries. Full output arrays match exactly across both layouts and all replicas before measurement, and after every timed arm. No new driver errors occur.

| K × rows | Columns | Streamed GPU time reduction: first / repeat |
|---|---:|---:|
| 5120 × 17408 | 1 | 6.3% / 4.1% |
| 17408 × 5120 | 1 | 5.6% / 2.9% |
| 5120 × 17408 | 2 | 8.1% / 5.7% |
| 17408 × 5120 | 2 | 9.8% / 8.8% |

These are geometric block contrasts, not token throughput. The first pass's descriptive 95% intervals cross zero for the two C1 streamed shapes; the repeat's four streamed intervals exclude zero. There are only three blocks per condition and temporal correlation remains possible. Telemetry is process-wide rather than attributed precisely to each arm. GPU clocks vary substantially, and the two monitor files contain 12 and 14 sensor-read EBUSY errors respectively. These do not invalidate timestamp retrieval or numerical checks, but prevent a strict per-arm clock-matched qualification. Treat this as evidence supporting model integration, not a general speed guarantee. Cached means also improve, but are less representative of model-wide weight streaming. [First-pass results](../archive/isolated/q3-pad112/timing/20261028T230046Z/summary.json), [reversed-order repeat](../archive/isolated/q3-pad112/timing-confirmation/20261028T230156Z/summary.json).

One matrix is 38,297,600 native bytes and can fit the R9700's 64 MB Infinity Cache. Streamed tests rotate **16 distinct matrix replicas**, totaling 612,761,600 native bytes or 623,902,720 padded bytes per variant. Exceeding only its 8 MiB L2 would give misleading cache coverage. [AMD product specifications](https://www.amd.com/en/products/graphics/workstations/radeon-ai-pro/ai-9000-series/amd-radeon-ai-pro-r9700.html), [AMD cache specifications](https://rocmdocs.amd.com/en/develop/reference/gpu-specs.html).

## Private model integration

A separate opt-in host now prepares padded copies with a GPU repacker. Six capped repacker cases pass exact byte, source-immutability and guard checks, including block-count tails; no new driver errors occur. [Repacker checks](../archive/isolated/q3-pad112/repack-diagnostics/checks.json), [shader](../archive/isolated/q3-pad112/repack.comp).

The experiment requires an explicit immutable-WEIGHTS contract and handles only contiguous, non-view Q3 C1/C2 matrices on this device. Other shapes and prefill retain native buffers/pipelines. Each inference context owns its cache, original buffer references and custom pipelines, and cleans them after GPU synchronization. An 8 GiB cache cap and 4 GiB free-VRAM reserve gate allocations. Keeping both formats costs a full Q3 weight copy plus padding, not merely 1.82% VRAM. General mutable-weight support is not implemented; this is a private immutable-model experiment.

The 32-token model gate passed: all 38 requested target-logit rows, tokens and acceptance counters match the native reference byte for byte (SHA-256 `75055a49a5844ad14030f45cb76c11de20a44a6bb0e2db7c1c89a616137eb576`). The cache contains 78 matrices / 3,041,525,760 bytes (2.83 GiB) and records 1,560 padded dispatch calls. There are no new driver errors. This target-only audit does not capture draft logits or hidden states. [Model comparison](../archive/isolated/q3-pad112/model32/comparison.json).

The fixed 18-arm stock/private-control/padded throughput test completed. Every arm matches all 513 generated tokens, 279 drafted and 234 accepted counts, with zero new driver errors and valid timed telemetry. All three blocks fail at least one CPU/build/clock comparability condition as compilation load changes. The geometric padded/private-control effect is +0.71%, with a descriptive interval of −21.49% to +29.18%; this establishes neither a gain nor a regression. Stock throughput itself ranges from about 23 to 35 tokens/s. [Full-model analysis](../archive/isolated/q3-pad112/model-under-load512/20261028T230812Z/confirmation-analysis.json). The private control uses the same host with padding disabled. Timing preserves encoding, cold and total costs as well as steady throughput. [Predeclared model timing plan](../archive/isolated/q3-pad112/model-timing-plan.json). Claude's checkout, deployed binaries and original model files are unchanged.


The shorter resident-model diagnostic completed: one unmeasured padded warmup plus 24 fixed 128-token generations in six alternating ABBA/BAAB blocks. It synchronizes and clears target/draft model memories, creates fresh samplers/speculator, and keeps the model, contexts and both weight formats resident between arms. This reduces reload gaps while preserving native/padded pipeline selection on every backend graph recording. All output tokens/counters must match across all 25 generations. This compares the private host only; it does not directly replace the unmodified-stock test. [Resident-model protocol](../archive/isolated/q3-pad112/inprocess-plan.json).

## What the workload changes

The full-model run samples GPU busy at roughly 45–55% during saturated compilation, versus about 74% in the lower-contention middle section. That is consistent with host submission/scheduling limiting GPU utilization, though it does not prove a single cause. Main-thread scheduling-delay counters are unavailable in this kernel, so only CPU execution time was observed. Faster weight loads cannot remove the rest of the token's work, and the same small operator gain may be hidden by CPU contention. [Utilization and VRAM observations](../archive/isolated/q3-pad112/model-under-load512/20261028T230812Z/utilisation-summary.json).


## Resident-model result and allocation follow-up

The repeat with persisted child status exits normally (code 0), has no new driver errors and matches tokens/counters across all 25 generations. The 24 timed arms average **21.33 tokens/s native control versus 20.04 padded**. The mean log block contrast is **−5.94%**, with descriptive 95% interval **[−12.29%, +0.87%]**. All six blocks pass the predeclared CPU/build/clock checks. **No gain is supported; the padded prototype appears slower in this test.** Saturated CPU utilization and equal build-process counts still cannot guarantee identical runnable-thread pressure. [Checks](../archive/isolated/q3-pad112/inprocess/20261028T232146Z/checks.json), [analysis](../archive/isolated/q3-pad112/inprocess/20261028T232146Z/analysis.json), [execution status](../archive/isolated/q3-pad112/inprocess/20261028T232146Z/execution.json).

The first resident attempt also completes 25 identical generations, but the report parser fails before persisting the GPU child's exit code. Its recovered timings are retained as unqualified evidence. A fixed repeat was chosen to preserve execution status before parsing, regardless of recovered timing results. The repeat's report parser also required CPU-only correction of an escaped expression; the GPU execution status and driver checks had already been persisted. No GPU inputs or timing results were edited, and no model crash occurred. The corrected standalone parser verifies all saved generations. [Parser source](../archive/isolated/q3-pad112/parse_inprocess.py).

One integration difference is now under test: the operator benchmark stores its replicas in a few large buffers, but the model cache creates **78 separate Vulkan buffer/memory allocations**. An arena prototype places the same 78 padded matrices into one 3 GiB buffer, keeping their descriptor ranges exact and offsets aligned. This could reduce driver bookkeeping or change memory/TLB behaviour; it is a hypothesis, not an established cause. Its native control uses the same new host with padding disabled. Model correctness must pass before the fixed resident-model timing protocol runs.


The arena's first resident-model test completes 25 identical generations with exit0 and no new driver errors. Its 24 measured arms average **34.05 native-control versus 34.66 padded tokens/s**. Six symmetric block contrasts give **+1.82%**, descriptive 95% interval **[+0.25%, +3.42%]**; all six pass the declared comparability checks. This is a promising private-host result, not yet an independently confirmed stock-backend gain. Build counts are zero during this test, while background CPU utilization remains roughly56–67%; the earlier separate-buffer run had saturated compilation. Therefore the difference between their results does **not** establish allocation count as the cause. [Arena checks](../archive/isolated/q3-pad112/arena-inprocess/20261028T232836Z/checks.json), [arena analysis](../archive/isolated/q3-pad112/arena-inprocess/20261028T232836Z/analysis.json), [arena patch](../archive/isolated/q3-pad112/arena-cache.patch).

A predeclared independent 18-process, 512-token stock/control/arena confirmation follows, retaining the same order and comparability rules used earlier. Two additional coding/math target-logit audits are also scheduled serially. [Independent confirmation plan](../archive/isolated/q3-pad112/arena-confirmation-plan.json).

## Within-generation diagnostic

A final diagnostic alternates the native and padded path between target verification calls, using a seeded balanced4-call schedule. Sixteen calls warm the cache;768C2 calls form12fixed64-call blocks. The model stays loaded and generated output matches the first513stock tokens. EOS suppression and a bounded call count define this longer synthetic trajectory; it is not the earlier normal stopping/acceptance workload.

The first attempt times asynchronous `llama_process` return, which measures enqueue/host-recording cost. It is retained with that limited scope. A separate repeat explicitly synchronizes the target context before stopping the timer, thereby including GPU completion. Both exit0 with no new driver errors. The synchronized result is **−2.66% target-verification speed**, descriptive95% interval **[−5.18%, −0.07%]**. Eleven blocks pass matching; one fails during a load transition, so the all-block qualification gate fails. This is not a full-token-throughput or unmodified-stock comparison. Early compilation-heavy blocks favour native; later lighter-load blocks are near zero or slightly positive. Do not select those later blocks to claim a win. [Synchronized stage analysis](../archive/isolated/q3-pad112/interleaved-sync/20261028T234721Z/analysis.json).

The enqueue-only diagnostic averages7.65ms of main-thread CPU for native versus8.85ms for padded, within the same mixed-mode process. This suggests host-side overhead deserves profiling, but includes any waits inside `llama_process` and may be affected by switching formats/descriptor bindings. It does not isolate the cache lookup itself or establish a constant1.2ms penalty for a permanently enabled padded model. [Enqueue CPU diagnostic](../archive/isolated/q3-pad112/interleaved/20261028T234518Z/enqueue-cpu-summary.json).

The actual stock library's embedded Q3 SPIR-V has also been extracted read-only and matches the microbenchmark's native module byte for byte. A mismatched native shader control is therefore ruled out for this module. [Embedded-module proof](../archive/isolated/q3-pad112/stock-module-proof.json).
